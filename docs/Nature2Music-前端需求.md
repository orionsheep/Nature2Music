# Nature2Music 前端需求文档

> 版本：v1.0（2026-08-11）
> 用途：交付给前端设计/开发工具，基于已跑通的 Nature2Music 后端管线封装 Web 前端。

---

## 1. 产品概述

**Nature2Music** 是一个「自然声音 → 音乐」的 AI 生成工具。用户上传一段自然声音（鸟叫、虫鸣、雨声、雷声等），系统完成三步处理：

1. **声学生物识别**（Fun-ASR LoRA 微调模型）：识别声音来源的物种/类别，输出结构化 JSON；
2. **音频特征分析**：提取时长、BPM、主频、频谱质心等特征；
3. **音乐生成**（ThinkSound 扩散模型）：基于识别结果和音频特征生成一段风格化的环境音乐。

**核心价值主张**：把一段 5 秒的自然录音，变成一段可聆听、可下载的音乐作品，并向用户透明展示「AI 听到了什么、如何理解、如何创作」的完整推理链。

**运行环境**：本地运行（macOS M4 Pro），端到端生成耗时约 **2 分钟**，无 GPU 服务器依赖。前端通过本地后端服务调用 CLI 管线。

---

## 2. 目标用户

- 自然录音爱好者 / 声音设计师：把田野录音快速变成音乐素材；
- 音乐创作者：寻找生物声学灵感的独特音色与动机；
- 科普/教育场景：演示「AI 理解自然声音」的完整过程。

---

## 3. 核心用户流程（主链路）

```
上传/录制音频
    ↓
识别中（约 15 秒）→ 展示识别结果卡片（物种、置信度、音频特征）
    ↓
用户确认/调整生成参数（风格、时长）→ 可编辑 AI 生成的提示词
    ↓
生成中（约 100 秒，需明确的进度反馈）
    ↓
音乐播放器（播放/波形可视化）+ 识别过程回顾 + 下载音频/报告
```

### 3.1 状态机

页面必须覆盖以下状态：

- **空状态**：引导上传（拖拽区 + 示例音频入口）；
- **识别中**：轻量等待（~15s），可显示识别动画；
- **识别完成**：结果卡片 + 参数面板，等待用户触发生成；
- **生成中**：长任务（~100s），需要分阶段进度提示（特征提取 → 扩散采样 → 解码），允许取消；
- **完成**：播放器 + 完整报告；
- **失败**：识别失败 / 生成失败 / 音频格式不支持，均给出可操作的错误提示和重试入口。

## 4. 功能需求

### 4.1 音频上传模块

- 支持拖拽上传和点击选择文件；
- 支持格式：WAV / MP3 / FLAC / OGG / M4A（后端统一转 44.1kHz）；
- 时长限制：建议 3–30 秒，超出给出提示（模型按 5 秒样本训练，过短识别不准，过长无收益）；
- 提供 **3–5 条内置示例音频**（鸟叫、虫鸣、雨声、雷声、蛙鸣各一），让首次用户一键体验；
- （可选增强）支持浏览器麦克风现场录音；
- 上传后显示源音频的波形图和基础信息（时长、采样率）。

### 4.2 识别结果展示模块

识别接口返回的结构化 JSON（字段即后端真实 schema，不得更改）：

```json
{
  "group": "bird",
  "species": "crow",
  "confidence": 1.0,
  "scientific_name": "Corvus",
  "common_name_zh": "乌鸦",
  "call_type": "song",
  "background": [],
  "raw_text": "..."
}
```

界面要素：

- **物种卡片**：中文名（主）+ 英文名 + 学名（斜体），配类别图标（bird / insect / mammal / amphibian / environment 五大类）；
- **置信度**：百分比 + 可视化条形；低于 0.6 时提示「识别可能不准确，生成结果仅供参考」；
- **叫声类型**（call_type：song / call / drumming 等）与**背景声**（background 数组，空则不显示）；
- **音频特征面板**（来自 `audio_features`）：

```json
{
  "duration_s": 5.0,
  "sample_rate": 44100,
  "rms": 0.0825,
  "spectral_centroid_hz": 2348.79,
  "dominant_frequency_hz": 32.3,
  "estimated_bpm": 60.09
}
```

- 特征以「可读懂」的方式呈现：如「估计节奏 60 BPM」「主频 32 Hz」「响度适中」，而非只罗列数字；BPM 和主频会被用于生成，建议用微文案说明这一关联。

**能力边界（必须如实告知用户）**：当前模型在 ESC-50 的 15 个类别上微调：cat、chirping_birds、crickets、crow、dog、frog、hen、insects、rain、rooster、sea_waves、sheep、thunderstorm、wind、crackling_fire。上传范围外的声音（如人声、乐器）可能误识别，界面上应在帮助/说明区注明。

### 4.3 生成参数模块

- **音乐风格**（`--style`，自由文本 + 预设标签）：
  - 预设建议：`ambient 氛围`、`中国风管弦（ambient Chinese orchestral）`、`lo-fi 低保真`、`电影配乐 cinematic`、`电子 ambient`、`极简钢琴`；
  - 用户可自定义输入英文描述（后端直接拼入 prompt，当前模型对英文 prompt 效果最稳）；
- **生成时长**（`--duration`）：滑块 2–30 秒，默认 10 秒；标注「时长越长生成越慢（10 秒约 2 分钟）」；
- **提示词预览与编辑**（差异化亮点）：
  - 系统根据识别结果自动生成两段提示词——`caption`（一句话）和 `chain_of_thought`（详细创作说明），展示给用户；
  - 高级用户可展开编辑后再生成（对应后端 `compose` 命令接受自定义 recognition JSON）；
  - 示例（真实输出）：
    - caption: `ambient Chinese orchestral music inspired by the call of 乌鸦`
    - chain_of_thought: `Create a coherent ambient Chinese orchestral music composition at approximately 60 BPM. The ecological focus is 乌鸦 (Corvus), a bird vocalization with call type song. ...`

### 4.4 生成过程模块

- 生成是**长任务**（10 秒音频约 2 分钟），必须异步执行：
  - 前端轮询或 WebSocket 获取进度；
  - 分阶段展示：`提取音视频特征（约 40s）→ 扩散采样生成（约 40s）→ 音频解码`；
- 提供取消按钮（终止后端子进程）；
- 生成期间允许用户继续查看识别结果，但禁止重复提交。

### 4.5 结果展示与播放模块

- **音乐播放器**：播放/暂停、进度条、音量、**波形可视化**（推荐 wavesurfer.js）；
- 音频规格：44.1kHz 立体声 WAV，时长即用户设定值；
- **创作回顾区**：并排展示「源声音波形 ↔ 生成音乐波形」，强化「从自然到音乐」的叙事感；
- **下载**：WAV 音频 + 完整 JSON 报告（`run_report.json`，含输入路径、识别结果、音频特征、完整 prompt）；
- （可选）「再生成」按钮：相同参数重跑（扩散模型每次结果不同）。

### 4.6 历史记录模块

- 本地持久化（后端写文件/SQLite 均可）最近 20 条生成记录：
  - 缩略信息：物种名、风格、时长、生成时间；
  - 点击可重新加载结果（音频 + 报告），不重新生成；
- 支持删除单条记录。

---

## 5. 页面结构

单页应用（SPA）即可，不建议多页面：

| 区域 | 内容 |
|---|---|
| 顶部导航 | 产品名 + 简介入口 + 「能力边界」说明弹窗入口 |
| 主工作区（左/上） | 上传区 → 识别结果卡片 → 参数面板 → 生成按钮 |
| 结果区（右/下） | 播放器 + 波形对比 + 下载区 |
| 历史区（抽屉或底部） | 历史记录列表 |
| 全局 | 长任务进度浮层、错误 toast |

移动端做基础响应式即可（竖排堆叠），优先级低于桌面端。

---

## 6. 后端接口需求（前端依赖的 API）

当前后端是 CLI（`nature2music run/identify/compose`），需封装一层本地 HTTP 服务（建议 FastAPI），向前端暴露：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/identify` | POST | 上传音频，返回识别 JSON + audio_features（同步，~15s） |
| `/api/generate` | POST | 参数：recognition JSON（可含用户编辑过的 prompt）、style、duration；返回 task_id |
| `/api/tasks/{id}` | GET | 查询任务状态：pending / extracting / sampling / decoding / done / failed + 进度描述 |
| `/api/tasks/{id}` | DELETE | 取消任务 |
| `/api/results/{id}/audio` | GET | 下载生成的 WAV |
| `/api/results/{id}/report` | GET | 下载 run_report.json |
| `/api/history` | GET/DELETE | 历史记录列表 / 删除 |
| `/api/samples` | GET | 内置示例音频列表 |

注意：生成任务必须子进程异步执行，**不能阻塞 HTTP 请求**；同一时刻只允许一个生成任务（本地单卡内存约束）。

---

## 7. 非功能需求

- **性能**：识别 ≤20s 有反馈；生成全程有进度反馈，不允许出现「无响应」观感；
- **错误处理**：音频解码失败、模型未加载、内存不足、任务中断，均需 toast + 重试入口；
- **隐私**：全部本地处理，界面上可标注「音频不离开本机」作为卖点；
- **浏览器兼容**：Chrome / Edge / Safari 最新两个版本；
- **语言**：界面中文为主，prompt 内容保留英文原文。

---

## 8. 视觉与设计方向

- **气质**：自然、安静、专业。联想词：森林、声谱、晨雾、田野录音工作室；
- **配色**：深色系为主（接近音频工作站工具），主色建议从自然色中取（苔绿 / 深湖蓝），强调色一个即可（如琥珀橙，用于生成按钮和波形）；
- **关键视觉元素**：声波/频谱图形贯穿全站；物种卡片可用简约线条插画或类别图标；
- **字体**：中文思源黑体/苹方，数字与代码用等宽字体（体现「音频工程」感）；
- **动效**：克制的过渡动画；生成中可用「声波呼吸」式的等待动画，避免廉价感的旋转 loading；
- **避免**：通用 AI 产品的紫蓝渐变 + 大圆角卡片套路。

---

## 9. 技术建议（供参考，不强制）

- 框架：React / Vue 3 + Vite；
- 波形：wavesurfer.js（v7+）；
- 状态：轻量即可（Zustand / Pinia）；
- 后端封装：FastAPI + subprocess 调用现有 CLI，或直接 import `nature2music.pipeline`；
- 构建产物为纯静态页 + 本地服务，不需要账号体系、不需要部署到公网。

---

## 10. 验收标准

1. 用户从上传到听到音乐，全程无需接触命令行；
2. 识别结果、音频特征、prompt、生成音频四要素在同一界面闭环展示；
3. 2 分钟生成过程中用户始终知道「进行到哪一步、还要等多久」；
4. 失败场景（错误格式 / 识别失败 / 生成中断）均有明确提示与重试路径；
5. 示例音频一键体验路径 ≤3 次点击出声。
